## O. Store-manager scoping & receiving
- Role **Maison Manager** is store-scoped via User Permission on Warehouse + `Maison Associate.boutique`; enforce server-side in every endpoint (scoping.py) and in desk list views (permission_query_conditions) so a manager sees only their store's Stock Entries, Purchase Receipts, Material Requests, Stock Alerts, Sales Invoices, Employees/shifts, feedback, cycle counts. Add tests proving manager A cannot read/write store B docs (HTTP-level, not only unit).
- **Receiving at the store** (POS screen "Receive"): list inbound shipments for this store (`Maison Shipment` from the warehouse, status Shipped/In transit) and open POs shipped directly by vendors to the store; open one → scan items (barcode) or tap to count → discrepancies highlighted → "Confirm receipt" creates the Stock Entry (Material Transfer receipt leg: ERPNext "Material Transfer" from `HOU-WH` to store warehouse executed as an in-transit flow: warehouse posts Material Transfer to `<store> In Transit` on ship; store receipt posts `In Transit` → store warehouse on confirm; or a Purchase Receipt against the PO for vendor-direct). Partial receipt supported; short/over/damaged quantities recorded on `Maison Shipment` lines and raise a `Maison Receiving Discrepancy` for the warehouse admin. Managers can also create a **Replenishment Request** (Material Request, type Material Transfer, from HOU-WH) from the low-stock list with one tap ("Request from warehouse") or manually.

## P. Warehouse & shipping module (head office, Houston)
- Role **Maison Warehouse Admin**. Flow: store Replenishment Request (Material Request) → warehouse admin **Approve / Edit quantities / Reject** (workflow `Maison Replenishment Approval`; rejections notify the manager with reason) → on approve, a **`Maison Shipment`** is created (store, lines item/qty/picked_qty, status Pending → Picking → Packed → Shipped → Received; weight/dims estimate from item fields `weight_per_unit`, `maison_length/width/height`; packing list no; carrier; service; rate; label_url; tracking_no; created_by; timestamps) + Pick List. The shipment posts the Material Transfer (store In-Transit) at **Shipped**.
- **Rate shopping**: adapter interface `maison_pos/shipping/providers/{base,simulated,shippo,easypost}.py` — `rates(from, to, parcels) -> [{carrier, service, amount, days, provider_rate_id}]`, `buy(rate) -> {label_url, tracking_no, tracking_url}`, `track(tracking_no)`. Default provider Simulated (realistic USPS Priority/UPS Ground/FedEx Home tiers by zone/weight). **Shippo** implemented for real (API key in site_config `shippo_api_key`; test mode supported); Pirate Ship has no public API — documented in docs/shipping.md with the recommendation (Shippo free tier includes API; same USPS Commercial Plus / UPS discounted rates as Pirate Ship; EasyPost as alternative). "Cheapest" is auto-selected with a "fastest" toggle; admin can override. Endpoints `shipping.rates(shipment)`, `shipping.buy(shipment, rate_id)`, `shipping.track(shipment)`, `shipping.mark(shipment, status)`, `shipping.pack(shipment, lines, parcels)`; scheduled tracking refresh hourly; Maison Boutique ship-to address fields; HQ ship-from in settings.
- **Warehouse Wall** (`/warehouse-wall`, 55" landscape 1920×1080/4K): a kanban-style board Pending approval · To pick · Packing · Ready to ship (label bought) · Shipped today, each card = store code + name, items/units, age timer (turns warn at 4 h, crit at 24 h), carrier/service when chosen, priority (low-stock-driven requests marked ⚑). Realtime over socket.io; auto-refresh fallback 10 s; large type; gold system; sound/flash on new approved shipment (toggle). Touch-friendly: warehouse staff can tap a card → Pick (shows pick list with bin/locations), Packed, Buy label (shows rates, cheapest pre-selected), Print packing list, Ship. **Auto-print packing list**: when a shipment becomes Approved (and again on Ready to ship for the label), the wall page opens the packing list print (`Maison Packing List` print format: store ship-to, lines with barcodes, cartons, weight, QR of shipment) via an iframe `window.print()`; document running Chrome in kiosk mode (`--kiosk --kiosk-printing`) on the PC attached to the 55" screen and printer so it prints silently; alternatively a tiny print agent (`docs/shipping.md`); label PDF printed the same way on a 4×6 label printer (second printer via kiosk default: document the Windows printer-selection limitation and the agent approach).
- **Warehouse Admin desk**: POS-style web screen `/warehouse` (list of requests, approve/edit/reject, shipments, discrepancies, stock on hand at HOU-WH, inbound vendor POs, receive vendor PO at warehouse with scan, low-stock at warehouse). Reuse the POS bundle (route group) with role gating.
- Dashboard (Command): "Supply" tile: open requests, shipments in transit, avg approve→ship hours, discrepancies.
- Tests: approval workflow, shipment lifecycle + stock postings (in-transit), partial receipt + discrepancy, rate adapter (simulated), Shippo adapter with mocked HTTP, wall endpoint scoping; e2e: manager requests from low-stock → admin approves on /warehouse → wall shows card + triggers print (assert print hook) → rates → buy (simulated) → ship → store receives with scan → stock moves.

## Q. Rewards program (client's spec) — on top of ERPNext Loyalty + our coupons/campaigns
Program "CloudChaserz Rewards": **$1 = 1 point** (conversion factor 1, on net paid amount excl. tax), redemption **$5 off at 100 points, $10 at 200, $15 at 300** (fixed tiers — implement as `Maison Reward Tier` rows under the program; POS "Redeem" shows only the tiers the client can afford, one tier per transaction by default, setting to allow stacking), points never negative, reversed on returns. **Birthday discount**: configurable % or $ coupon auto-issued 7 days before birthday, valid 30 days (uses Maison Coupon + campaign touch). **Monthly sale promotions**: `Maison Promotion Calendar` (month → Pricing Rules + featured items → auto campaign send on the 1st). **Latest product arrivals**: "New arrivals" auto-segment campaign weekly from Website Items/Items created in last 14 days (per store availability). **Product giveaways**: `Maison Giveaway` (name, prize item, entry rule: 1 entry per $X or per visit, start/end, winner drawn randomly with seed + audit, notify) — POS shows "N entries" on the receipt/Salon. **Exclusive event invites**: campaign channel Event with RSVP link on the public receipt/Salon ("Invite me") already exists (private viewing) → rename generic "Events". Public rewards page `/rewards` on the webshop with the exact copy above and sign-up form (name, phone/email, birthday, consent), and the Salon "Join" flow uses the same copy. Receipt prints points earned, balance, "next reward at N points". Tests: tier redemption math, birthday coupon issuance job, giveaway entries + draw, reversal on return.
